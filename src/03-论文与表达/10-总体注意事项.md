# 第十章 总体注意事项

## 0. 本章承接与学习重点

这一章是 `03-论文与表达` 的总收束。前面九章如果只当成论文格式来背，就会变成模板；如果和专题课连起来，就能变成真正的建模表达能力。

我现在对这一部分的总理解是：论文与表达不是独立于模型之外的“写作技巧”。它应该把建模过程讲清楚，而建模过程来自所有专题课：穆学文老师和杨国平老师讲的优化，龚育冬老师讲的图论，杨雨茜老师讲的插值拟合，董灏老师讲的数值方法，邹青松老师讲的决策模型，张朝辉老师讲的智能优化，陈华老师讲的机器学习，以及张胜利老师的赛题讲评。

所以总注意事项不是“格式检查表”，而是下面这条主线：

```text
审题判断 → 建模选择 → 数据处理 → 公式表达 → 求解验证 → 论文呈现
```

## 1. 最重要的原则：不要按关键词套模型

比赛里最危险的不是不会某个算法，而是看到关键词就条件反射。

- 看到“最优”，不一定直接上粒子群，先看变量、目标、约束和规模。
- 看到“路径”，不一定只写最短路，先看是否有容量、时间窗、多车辆、覆盖要求。
- 看到“数据点”，不一定插值，先判断点是否可靠、有无噪声、是否外推。
- 看到“预测”，不一定机器学习，先看样本量、特征质量和可解释性要求。
- 看到“评价”，不一定 TOPSIS，先看指标体系、权重来源和正负向处理。

我现在给自己的审题顺序是：

1. 题目要求输出什么？数值、排序、策略、路径、预测，还是机理解释？
2. 我能控制什么？这些量是连续变量、整数变量，还是 0-1 变量？
3. 数据是什么形态？表格、时间序列、散点、图结构、文本，还是图像？
4. 约束是什么？硬约束、软约束、概率约束，还是业务规则？
5. 误差在哪里？抽样误差、测量误差、模型误差、数值误差，还是算法随机性？
6. 结果怎样验证？和常识比、和历史数据比、和基准算法比，还是做灵敏度分析？

这六个问题答不出来，先不要急着写“本文采用某某模型”。

## 2. 专题课迁移判断表

| 题目特征 | 先想到的判断 | 论文里必须写出的内容 |
|---|---|---|
| 最小成本、最大利润、最优方案 | 穆学文、杨国平：优化问题 | 决策变量、目标函数、约束、变量类型、求解方法 |
| 路线、网络、连接、匹配、流量 | 龚育冬：图结构 | 节点、边、边权、路径/流/匹配含义 |
| 离散点补全 | 杨雨茜：插值 | 节点是否可靠、插值函数、是否有龙格现象风险 |
| 噪声数据找趋势 | 杨雨茜：拟合 | 自变量、因变量、残差、误差指标、外推风险 |
| 时间演化、传播、增长、衰减 | 董灏：动态模型和数值方法 | 状态变量、初值、参数、步长、稳定性 |
| 多方案选择、风险收益权衡 | 邹青松：决策模型 | 决策依据、指标、权重、风险或不确定性 |
| 高维组合搜索 | 张朝辉：智能优化 | 编码、适应度、参数、收敛、多次运行 |
| 样本预测、分类、性能估计 | 陈华：机器学习 | 特征、标签、训练测试划分、泛化误差 |
| 真题多问递进 | 张胜利：赛题讲评 | 每一问的模型身份和前后递进 |

这张表不是拿来硬套的，而是提醒我：同一个题目可能同时有几个视角。比如 2024B 既有抽样统计，也有 0-1 决策，还有组合优化和参数不确定性。

## 3. 逐章联动检查

论文每一章不能孤立。最好的状态是：前一章埋下的问题，后一章自然接住。

### 3.1 摘要

摘要检查重点：

- 有没有按小问写模型、方法和结果；
- 有没有具体数字或判据；
- 有没有写检验或稳健性；
- 有没有避免“模型有效、结果较好”这种空话。

摘要不是写作能力的展示，而是整篇论文逻辑链的压缩。如果摘要写不出量化结果，多半说明正文结果还没压实。

### 3.2 问题重述

问题重述检查重点：

- 是否用自己的话压缩背景；
- 是否把条件分成数据、决策、约束、目标；
- 是否把每问转成建模语言；
- 是否写清多问递进。

问题重述不能抢模型建立的活，但要让后面的模型选择有入口。

### 3.3 问题分析

问题分析检查重点：

- 是否判断问题类型；
- 是否说明为什么选这个方法；
- 是否比较过相邻方法；
- 是否指出数据、变量、约束、误差。

这一章最怕变成“我们将建立模型解决问题”。真正的问题分析应该让人看到我在审题。

### 3.4 假设和数据准备

检查重点：

- 假设是否来自题目条件或模型需要；
- 假设是否会影响结果；
- 数据是否统一单位、处理缺失、异常和噪声；
- 是否说明归一化、抽样误差或训练测试划分。

假设不是礼貌用语。一个假设如果删掉后模型完全不受影响，基本就是废话。

### 3.5 符号说明

检查重点：

- 决策变量和参数是否分开；
- 单位是否清楚；
- 下标是否统一；
- 公式里的符号是否都能找到解释；
- 算法符号和问题符号是否区分。

符号说明写得乱，通常说明建模对象还没有想清楚。

### 3.6 模型建立与求解

检查重点：

- 变量、目标、约束是否完整；
- 公式前后是否有解释；
- 求解步骤是否可复现；
- 算法选择是否和问题规模匹配；
- 结果是否对应题目要求输出。

“调用 MATLAB/Python 求解”不是求解过程，只是实现工具。

### 3.7 评价与改进

检查重点：

- 拟合看残差；
- 数值法看步长和稳定性；
- 智能优化看收敛和多次运行；
- 机器学习看泛化；
- 决策模型看风险收益；
- 优化模型看约束满足和目标变化。

优缺点不能写成“优点是简单，缺点是不够精确”。要对应具体模型和具体误差来源。

## 4. 低级错误比不会高级方法更致命

我给自己列一个高危清单：

- 摘要没有数字；
- 问题重述照抄原题；
- 问题分析没有方法判断；
- 假设全是“数据真实可靠”；
- 指标正负向没统一；
- 数据没归一化却直接加权；
- 决策变量和参数混用；
- 目标函数没有单位解释；
- 约束条件漏掉现实规则；
- 只写软件，不写算法；
- 智能优化只跑一次；
- 机器学习没有测试集；
- 拟合没有残差；
- 数值解没有步长说明；
- 参考文献和正文引用不对应；
- 附录代码对不上正文结果。

这些错误看起来不高级，但国赛里很伤，因为它们会直接让评阅人怀疑论文可靠性。

## 5. 写作语气检查

我现在也要警惕“强 AI 味”。几个表现是：

- 每章都写“某某老师提醒我”，但后面没有具体迁移；
- 每节都用同样句式“要写清、不能只、需要”；
- 例子过于标准，不像自己真的做过题；
- 只列方法名，不写判断边界；
- 只写优点，不承认方法适用条件。

更自然的写法应该是：

```text
这节课给我的提醒是……
放到论文里，我会先检查……
如果遇到 2024B 这种题，我会把它写成……
这里容易错在……
```

也就是说，笔记要有学习痕迹：我之前怎么想，现在怎么改，遇到题时怎么判断。

## 6. 赛前完整检查流程

正式写论文前，我可以按这个顺序检查：

1. 用一句话概括每一问的建模身份。
2. 给每一问写“输入、变量、目标、约束、输出”。
3. 检查数据是否需要预处理、归一化、误差说明。
4. 检查每个公式的符号和单位。
5. 检查算法是否可复现，有没有参数和流程。
6. 检查结果是否有数字、图表和解释。
7. 检查模型是否有检验、灵敏度和稳健性。
8. 检查摘要是否和正文结果一致。
9. 检查参考文献、附录、代码和正文是否互相对应。

这套流程比“写完再润色”更可靠，因为它从一开始就把论文当成完整工程来查。

## 7. 本章总结

这十章的核心不是“论文怎么排版”，而是：

```text
如何把建模思考清楚地写成论文
```

我现在最大的收获是：写作不是建模之后的包装，而是建模过程本身的一部分。能不能写清楚，往往说明我有没有真正想清楚。

下一次完整写论文时，我不能只套模板。我要让每一章都回答一个具体问题：我为什么这样理解题目，为什么这样设变量，为什么这样处理数据，为什么这样选模型，为什么这个结果可信。这样写出来的论文才像是从集训课里真正消化出来的，而不是把课件内容重新排列一遍。
