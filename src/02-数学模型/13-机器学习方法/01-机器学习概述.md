# 13.1 机器学习概述

**机器学习**（Machine Learning）通过数据学习输入与输出或数据内部结构，而不是为每种情况手写规则。在数模中，它是**数据驱动建模**的重要补充：当机理不完整、关系非线性或特征较多时，ML 可以提供有竞争力的预测与分类结果，但仍需要合理的数据、验证设计和解释。

---

## 一、基本设定

给定训练数据 $\{(x_i, y_i)\}_{i=1}^n$ 或仅 $\{x_i\}$：

| 范式 | 标签 | 目标 | 例子 |
|------|------|------|------|
| **监督学习** | 有 $y$ | 学 $f:x\mapsto y$ | 回归、分类 |
| **无监督学习** | 无 $y$ | 发现结构 | 聚类、降维 |
| **半监督** | 少量 $y$ | 利用未标注 | 标签昂贵时 |
| **强化学习** | 奖励信号 | 学策略 | 博弈、控制（赛题较少） |

---

## 二、典型流程

```
问题定义 → 数据清洗与特征工程 → 划分训练/验证/测试
    → 选择模型 → 训练 → 调参与验证 → 测试集评估 → 解释与部署
```

**特征工程**往往比“换更复杂模型”更能提分：缺失值、标准化、编码类别、构造交互/滞后特征、降维等。

预处理步骤必须只在训练数据上“学习”，再应用到验证/测试数据。例如均值填补、标准化、PCA、特征筛选若在全数据上先做，会把测试信息泄漏给模型。推荐使用 `sklearn.pipeline.Pipeline` 将预处理和模型封装在同一验证流程中。

---

## 三、偏差–方差权衡

- **欠拟合**：模型太简，训练误差高（高偏差）  
- **过拟合**：死记训练噪声，泛化差（高方差）  

对策：更多数据、正则化、早停、交叉验证、集成、简化模型。

---

## 四、数模中何时用 ML？

| 更适合 ML | 更适合机理/统计模型 |
|-----------|---------------------|
| 特征多、关系黑箱 | 需要参数可解释、政策含义 |
| 预测精度优先 | 小样本、强先验机理 |
| 图像、文本、复杂表格 | 经典题型（优化、ODE、评价） |

机器学习不一定要取代机理模型。若题目已有明确规律，可以让机理模型负责解释，再用机器学习拟合残差或完成其中的预测环节；反过来，也可以先用简单的数据模型确认问题是否具有可预测性。

### 开始训练前先确认

1. 目标变量是什么，评价指标是否与题目决策目标一致？
2. 预测时真正可获得哪些特征，是否混入未来信息或目标的变形？
3. 样本量是否足以支撑模型复杂度，数据分布是否可能随时间变化？
4. 简单基线（均值、上一期、线性/Logistic 回归）表现如何？复杂模型必须稳定优于基线才有价值。

## 五、常用工具

| 库 | 用途 |
|----|------|
| `scikit-learn` | 预处理、经典模型、验证与指标 |
| `xgboost` / `lightgbm` | 梯度提升树，常用于表格数据 |
| `pytorch` / `tensorflow` | 深度学习 |
| `pandas` / `numpy` | 数据与数值 |

---

## 六、实验记录

至少记下随机种子、软件版本、数据划分、特征清单和模型参数。训练集、验证集、测试集用了哪些样本也最好保存下来。若结果会随随机划分明显变化，就报告几次实验或各折结果的均值与波动，不只保留最好的一次。

---

## 小结

机器学习部分真正费时间的往往不是调用模型，而是确认标签、整理特征和设计验证方式。后续各节分别介绍监督学习、无监督学习、集成方法和深度学习，评价方法统一放在 13.6。
